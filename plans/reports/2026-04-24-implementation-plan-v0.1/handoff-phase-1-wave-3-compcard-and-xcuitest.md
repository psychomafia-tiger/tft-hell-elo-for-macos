## Known quirks (don't trip on these)

1. **SourceKit false-positive diagnostics** — every new Swift file in the project prompts SourceKit to emit "Cannot find type X in scope" or "No such module XCTest/HotKey" warnings. These are IDE-only indexing lag. xcodebuild is authoritative. If xcodebuild succeeds + tests pass, ignore IDE diagnostics.

2. **XcodeGen idempotency** — Info.plist is regenerated from `project.yml info.properties` on every `xcodegen generate`. Do NOT hand-edit Info.plist directly — edit project.yml and regenerate.

3. **XCTest-host hotkey guard** — `TFTMacApp.init()` bails early if `XCTestConfigurationFilePath` env var is set. This is intentional (prevents System Settings spam on every `xcodebuild test` run). If Task 1.9 previews get added via `#Preview { TFTMacApp() }`, also add `XCODE_RUNNING_FOR_PREVIEWS=1` check (reviewer M1 note — currently unresolved).

4. **Debug vs Release arch** — Debug is active-arch-only (fast local builds), Release is universal (for .dmg distribution). If a subagent runs `xcodebuild clean` then universal Debug build → may fail on SPM package swiftmodule arch. Stick to Debug unless distribution testing.

5. **HotKey package** — pinned `exactVersion: "0.2.1"` to prevent silent upgrades (soffes/HotKey last meaningful release ~2020). If Task 1.9 somehow touches project.yml, preserve the pin.
